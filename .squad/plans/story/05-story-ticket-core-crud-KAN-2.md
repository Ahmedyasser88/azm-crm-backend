# Story 05 — Ticket Core CRUD, Categorization & History (Story: KAN-2)

## Prerequisites

- [01-story-customer-core-crud-KAN-1.md](01-story-customer-core-crud-KAN-1.md) completed: this story's `Ticket` entity references the existing `Customer` entity (`src/AzmCrm.Domain/Features/Customers/Customer.cs`) via a `CustomerId` foreign key, the same way `CustomerInteraction`/`CustomerNote` reference it. `Customer.cs` itself is **not** edited by this story.
- This is the first story in the KAN-2 ("Ticket Management System") slice and establishes the `Ticket` and `TicketHistory` aggregates that [06-story-ticket-assignment-KAN-2.md](06-story-ticket-assignment-KAN-2.md) and [07-story-ticket-status-escalation-KAN-2.md](07-story-ticket-status-escalation-KAN-2.md) extend by editing `Ticket.cs`, `TicketDto.cs`, `TicketListItemDto.cs`, `GetTicketsListQuery.cs`, and `TicketConfiguration.cs`.

## Story Goal

Give support agents REST endpoints to create and track support tickets against a customer, tag each ticket with a category and priority, and view the ticket's full change history — covering three of KAN-2's five acceptance criteria: "Create and track support tickets", "Assign categories and priorities to tickets", and (the write-side foundation, extended by Stories 06-07) "View complete ticket history".

Outcomes:
1. `POST /api/tickets` creates a ticket for an existing customer, with a category, a priority, and an initial `Status` of `New`.
2. `GET /api/tickets/{id}` returns a single ticket.
3. `GET /api/tickets` returns a paginated, filterable (`customerId`, `status`, `category`, `priority`) and searchable (title/description) list of tickets.
4. `PUT /api/tickets/{id}` edits a ticket's title, description, category, and priority, recording one `TicketHistory` row per changed field.
5. `GET /api/tickets/{id}/history` returns the ticket's complete chronological history, paginated, newest first.

**Not in scope for this story**: assigning a ticket to an agent (Story 06 adds `AssignedToUserId`), status-transition and escalation workflows beyond the initial `New` status (Story 07 adds `ChangeTicketStatusCommand`/`EscalateTicketCommand`), and deleting a ticket (not required by KAN-2's acceptance criteria, so no delete endpoint is implemented — `Ticket` still inherits `BaseEntity`'s `IsDeleted` for consistency with every other aggregate in this codebase, and `TicketConfiguration` applies the same `HasQueryFilter(t => !t.IsDeleted)` convention even though nothing sets it yet).

```csharp
using AzmCrm.Application.Shared.Exceptions;
using AzmCrm.Application.Shared.Interfaces;
using AzmCrm.Domain.Common;
using AzmCrm.Domain.Features.Tickets;
using MediatR;
using Microsoft.EntityFrameworkCore;

namespace AzmCrm.Application.Features.Tickets.Commands.CreateTicket;

internal sealed class CreateTicketCommandHandler(IApplicationDbContext dbContext)
    : IRequestHandler<CreateTicketCommand, Result<Guid>>
{
    public async Task<Result<Guid>> Handle(CreateTicketCommand request, CancellationToken ct)
    {
        var customerExists = await dbContext.Customers.AnyAsync(c => c.Id == request.CustomerId, ct);
        if (!customerExists)
            throw new NotFoundException($"Customer '{request.CustomerId}' was not found.");

        var ticket = new Ticket
        {
            CustomerId = request.CustomerId,
            Title = request.Title,
            Description = request.Description,
            Category = request.Category,
            Priority = request.Priority
        };

        dbContext.Tickets.Add(ticket);

        dbContext.TicketHistories.Add(new TicketHistory
        {
            TicketId = ticket.Id,
            EventType = TicketHistoryEventType.Created,
            Description = "Ticket created."
        });

        await dbContext.SaveChangesAsync(ct);

        return Result<Guid>.Success(ticket.Id);
    }
}
```

**Create file: `src/AzmCrm.Application/Features/Tickets/Commands/UpdateTicket/UpdateTicketCommandHandler.cs`**

```csharp
using AzmCrm.Application.Shared.Exceptions;
using AzmCrm.Application.Shared.Interfaces;
using AzmCrm.Domain.Common;
using AzmCrm.Domain.Features.Tickets;
using MediatR;
using Microsoft.EntityFrameworkCore;

namespace AzmCrm.Application.Features.Tickets.Commands.UpdateTicket;

internal sealed class UpdateTicketCommandHandler(IApplicationDbContext dbContext)
    : IRequestHandler<UpdateTicketCommand, Result>
{
    public async Task<Result> Handle(UpdateTicketCommand request, CancellationToken ct)
    {
        var ticket = await dbContext.Tickets.FirstOrDefaultAsync(t => t.Id == request.Id, ct)
            ?? throw new NotFoundException($"Ticket '{request.Id}' was not found.");

        if (ticket.Title != request.Title)
            dbContext.TicketHistories.Add(new TicketHistory
            {
                TicketId = ticket.Id,
                EventType = TicketHistoryEventType.Updated,
                Description = "Title changed.",
                OldValue = ticket.Title,
                NewValue = request.Title
            });

        if (ticket.Category != request.Category)
            dbContext.TicketHistories.Add(new TicketHistory
            {
                TicketId = ticket.Id,
                EventType = TicketHistoryEventType.Updated,
                Description = "Category changed.",
                OldValue = ticket.Category.ToString(),
                NewValue = request.Category.ToString()
            });

        if (ticket.Priority != request.Priority)
            dbContext.TicketHistories.Add(new TicketHistory
            {
                TicketId = ticket.Id,
                EventType = TicketHistoryEventType.Updated,
                Description = "Priority changed.",
                OldValue = ticket.Priority.ToString(),
                NewValue = request.Priority.ToString()
            });

        ticket.Title = request.Title;
        ticket.Description = request.Description;
        ticket.Category = request.Category;
        ticket.Priority = request.Priority;

        await dbContext.SaveChangesAsync(ct);

        return Result.Success();
    }
}
```

Note: `Description` changes are applied but not diffed into a `TicketHistory` row — free-text description edits are expected to be frequent and low-signal for an audit trail; only the structured fields (title, category, priority) are logged. Document this choice for reviewers (see Edge Cases).

**Create file: `src/AzmCrm.Application/Features/Tickets/Queries/GetTicketsList/GetTicketsListQueryHandler.cs`**

```csharp
using AzmCrm.Application.Features.Tickets.DTOs;
using AzmCrm.Application.Shared.Interfaces;
using AzmCrm.Application.Shared.Models;
using AzmCrm.Domain.Common;
using MediatR;
using Microsoft.EntityFrameworkCore;

namespace AzmCrm.Application.Features.Tickets.Queries.GetTicketsList;

internal sealed class GetTicketsListQueryHandler(IApplicationDbContext dbContext)
    : IRequestHandler<GetTicketsListQuery, Result<PaginatedResult<TicketListItemDto>>>
{
    public async Task<Result<PaginatedResult<TicketListItemDto>>> Handle(
        GetTicketsListQuery request, CancellationToken ct)
    {
        var query = dbContext.Tickets.AsQueryable();

        if (request.CustomerId is not null)
            query = query.Where(t => t.CustomerId == request.CustomerId);

        if (request.Status is not null)
            query = query.Where(t => t.Status == request.Status);

        if (request.Category is not null)
            query = query.Where(t => t.Category == request.Category);

        if (request.Priority is not null)
            query = query.Where(t => t.Priority == request.Priority);

        if (!string.IsNullOrWhiteSpace(request.Search))
        {
            var term = request.Search.Trim().ToLower();
            query = query.Where(t =>
                t.Title.ToLower().Contains(term) ||
                (t.Description != null && t.Description.ToLower().Contains(term)));
        }

        var totalCount = await query.CountAsync(ct);

        var items = await query
            .OrderByDescending(t => t.CreatedOn)
            .Skip((request.PageNumber - 1) * request.PageSize)
            .Take(request.PageSize)
            .Select(t => new TicketListItemDto(
                t.Id, t.CustomerId, t.Title, t.Category, t.Priority, t.Status, t.CreatedOn))
```

```csharp
using AzmCrm.Application.Features.Tickets.DTOs;
```

```csharp
using AzmCrm.Application.Shared.Interfaces;
using AzmCrm.Application.Shared.Models;
using AzmCrm.Domain.Common;
using MediatR;
using Microsoft.EntityFrameworkCore;

namespace AzmCrm.Application.Features.Tickets.Queries.GetTicketHistory;

internal sealed class GetTicketHistoryQueryHandler(IApplicationDbContext dbContext)
    : IRequestHandler<GetTicketHistoryQuery, Result<PaginatedResult<TicketHistoryDto>>>
{
    public async Task<Result<PaginatedResult<TicketHistoryDto>>> Handle(
        GetTicketHistoryQuery request, CancellationToken ct)
    {
        var ticketExists = await dbContext.Tickets.AnyAsync(t => t.Id == request.TicketId, ct);
        if (!ticketExists)
            throw new NotFoundException($"Ticket '{request.TicketId}' was not found.");

        var query = dbContext.TicketHistories.Where(h => h.TicketId == request.TicketId);

        var totalCount = await query.CountAsync(ct);

        var items = await query
            .OrderByDescending(h => h.CreatedOn)
            .Skip((request.PageNumber - 1) * request.PageSize)
            .Take(request.PageSize)
            .Select(h => new TicketHistoryDto(
                h.Id, h.TicketId, h.EventType, h.Description, h.OldValue, h.NewValue,
                h.CreatedBy, h.CreatedOn))
            .ToListAsync(ct);

        var result = new PaginatedResult<TicketHistoryDto>
        {
            Items = items,
            TotalCount = totalCount,
            PageNumber = request.PageNumber,
            PageSize = request.PageSize
        };

        return Result<PaginatedResult<TicketHistoryDto>>.Success(result);
```

## Edge Cases & Failure Modes

- **`CustomerId` on create does not resolve to an existing, non-deleted customer** — `CreateTicketCommandHandler` checks `dbContext.Customers.AnyAsync(...)` (the `Customer` query filter excludes soft-deleted rows) and throws `NotFoundException` → HTTP 404, identical to KAN-1 Story 02's interaction-create guard.
- **`GetById`/`Update`/`GetHistory` on a non-existent or soft-deleted ticket id** — `Tickets.FirstOrDefaultAsync`/`AnyAsync` return nothing because `TicketConfiguration.HasQueryFilter(t => !t.IsDeleted)` excludes soft-deleted rows; the handler throws `NotFoundException`, mapped to 404 by `ExceptionHandlingMiddleware.cs:33-37`.
- **`UpdateTicketCommandHandler` only logs `TicketHistory` rows for `Title`/`Category`/`Priority` changes, not `Description`** — a deliberate scope decision to keep the audit trail signal-to-noise ratio reasonable (free-text description edits are expected to be frequent); flag as a follow-up if agents need a full description diff history.
- **Updating a ticket without actually changing any of `Title`/`Category`/`Priority`** — `UpdateTicketCommandHandler`'s three `if` guards simply add zero `TicketHistory` rows; `SaveChangesAsync` still runs (harmless no-op `UPDATE`), and the command still returns `Result.Success()`.
- **Empty/whitespace `Search` term** — `GetTicketsListQueryHandler` only applies the search filter `when (!string.IsNullOrWhiteSpace(request.Search))`, mirroring `GetCustomersListQueryHandler`; an empty search returns the unfiltered (but still paginated/other-filtered) list.
- **`PageNumber`/`PageSize` out of range on either list endpoint** — enforced by `GetTicketsListQueryValidator`/`GetTicketHistoryQueryValidator` via the existing `ValidationBehavior` pipeline, turned into a 400 before the handler runs.
- **Combining `customerId`, `status`, `category`, `priority`, and `search` filters** — all five are applied as independent, AND-combined `Where` clauses in `GetTicketsListQueryHandler`; any subset (including none) is valid since every filter parameter defaults to `null`/empty.
- **Case-insensitive search is done in .NET (`.ToLower().Contains(...)`), not translated to a Postgres index** — same acceptable-for-now tradeoff already flagged in KAN-1 Story 01 for `GetCustomersListQueryHandler`.
- **Concurrent updates to the same ticket** — no optimistic concurrency token exists on `Ticket`; last-write-wins, consistent with `Customer`/`ApplicationUser` elsewhere in this codebase.
- **A hard delete of a `Customer` row** (never performed by this codebase — only `IsDeleted = true` soft-deletes exist) **would cascade-delete all of that customer's tickets** via `TicketConfiguration.HasOne(t => t.Customer).OnDelete(DeleteBehavior.Cascade)`. Since only soft delete is ever exercised, a soft-deleted customer's tickets remain in the table but become unreachable through `POST /api/tickets` (blocked at create time) and stay reachable by id/list for tickets created before the customer was deleted — call this out to reviewers, matching the same caveat KAN-1 Story 02 raised for interactions.
