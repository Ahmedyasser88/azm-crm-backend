# Story 26 — AI-Suggested Ticket Replies (Story: KAN-7)

## Prerequisites

- [25-story-ai-ticket-summaries-KAN-7.md](25-story-ai-ticket-summaries-KAN-7.md) completed: requires `IAiClient`, `OpenAiSettings`/`OpenAiClient`, and their DI registration in `src/AzmCrm.Infrastructure/DependencyInjection.cs`.
- Story 05 completed: requires `Ticket`, `IApplicationDbContext.Tickets`, `TicketsController`.

## Story Goal

Let an agent request an AI-drafted, customer-facing reply suggestion for a ticket, based on the ticket's title, description, and internal comment thread, satisfying KAN-7's "Suggest replies based on ticket context" acceptance criterion.

Outcomes:
1. `GET /api/tickets/{id}/suggested-reply` is a new, `[Authorize]`-protected (default) action returning a single suggested reply as plain text, generated by `IAiClient` from the same ticket context (`Title`/`Description`/`Category`/`Priority`/`Status`/recent `TicketComment`s) [25-story-ai-ticket-summaries-KAN-7.md](25-story-ai-ticket-summaries-KAN-7.md)'s `GenerateTicketSummaryCommandHandler` already assembles for its summary prompt.
2. The suggestion is **read-only and never persisted** — it is not stored on the `Ticket`, not attached to any `Conversation`, and not auto-sent. The agent copies the suggested text into the existing `POST /api/conversations/{id}/messages` call (`SendMessageCommand`, KAN-3 Story 08) exactly the way KAN-4 Story 15's `QuickReplyTemplate` body is copied into that same call — this codebase does not wire a `Ticket`'s suggested reply directly into a `Conversation` because no FK exists between the two aggregates (same reasoning documented in Story 25's Story Goal).
3. A failure to reach the AI provider returns a `Result` failure (HTTP 400) with a generic message, exactly as Story 25's summary endpoint does — this action never throws an unhandled exception for a provider-side failure.

**Not in scope**: multiple/ranked reply variants (always exactly one suggestion per call); auto-sending the suggestion; per-channel reply formatting (e.g. shorter text for SMS) — the same single suggestion text is returned regardless of what channel(s) a customer's conversations use; persisting or logging suggested replies for later review.

**Create file: `src/AzmCrm.Application/Features/Tickets/Queries/SuggestTicketReply/SuggestTicketReplyQueryHandler.cs`**

```csharp
using AzmCrm.Application.Features.Tickets.DTOs;
using AzmCrm.Application.Shared.Exceptions;
using AzmCrm.Application.Shared.Interfaces;
using AzmCrm.Domain.Common;
using MediatR;
using Microsoft.EntityFrameworkCore;

namespace AzmCrm.Application.Features.Tickets.Queries.SuggestTicketReply;

internal sealed class SuggestTicketReplyQueryHandler(IApplicationDbContext dbContext, IAiClient aiClient)
    : IRequestHandler<SuggestTicketReplyQuery, Result<TicketReplySuggestionDto>>
{
    private const int MaxCommentsInContext = 20;

    public async Task<Result<TicketReplySuggestionDto>> Handle(SuggestTicketReplyQuery request, CancellationToken ct)
    {
        var ticket = await dbContext.Tickets.FirstOrDefaultAsync(t => t.Id == request.TicketId, ct)
            ?? throw new NotFoundException($"Ticket '{request.TicketId}' was not found.");

        // Same bounded-context assembly as Story 25's GenerateTicketSummaryCommandHandler —
        // duplicated deliberately rather than extracted into a shared helper (see Context item 1).
        var comments = await dbContext.TicketComments
            .Where(c => c.TicketId == ticket.Id)
            .OrderByDescending(c => c.CreatedOn)
            .Take(MaxCommentsInContext)
            .OrderBy(c => c.CreatedOn)
            .Select(c => c.Content)
            .ToListAsync(ct);

        var userPrompt =
            $"Title: {ticket.Title}\n" +
            $"Category: {ticket.Category}\n" +
            $"Priority: {ticket.Priority}\n" +
            $"Status: {ticket.Status}\n" +
            $"Description: {ticket.Description ?? "(none)"}\n\n" +
            (comments.Count > 0
                ? "Internal comment thread (oldest first):\n" + string.Join("\n---\n", comments)
                : "No internal comments yet.");

        const string systemPrompt =
            "You are an assistant that drafts a polite, helpful, customer-facing reply for a support " +
            "agent to review and send. Address the customer's issue directly based on the ticket context " +
            "below. Keep it concise and professional. Do not invent facts not present in the ticket. " +
            "Return only the reply text, with no explanation of your reasoning.";

        string suggestedReply;
        try
        {
            suggestedReply = await aiClient.GetCompletionAsync(systemPrompt, userPrompt, ct);
        }
        catch (Exception ex) when (ex is not OperationCanceledException)
        {
            return Result<TicketReplySuggestionDto>.Failure(
                "AI reply suggestion is currently unavailable. Please try again later.");
        }

        return Result<TicketReplySuggestionDto>.Success(new TicketReplySuggestionDto(suggestedReply));
    }
}
```

[HttpGet("{id:guid}/suggested-reply")]
[ProducesResponseType(typeof(Result<TicketReplySuggestionDto>), StatusCodes.Status200OK)]
[ProducesResponseType(typeof(Result), StatusCodes.Status400BadRequest)]

public async Task<IActionResult> SuggestReply(Guid id, CancellationToken ct)

## Edge Cases & Failure Modes

- **Ticket id does not exist** — `SuggestTicketReplyQueryHandler` throws `NotFoundException` before any AI call, returning 404, identical to Story 25's handler.
- **AI provider unreachable/misconfigured/non-2xx** — caught by the handler's `try/catch`, returns a 400 `Result` failure with a generic message; nothing is persisted either way since this is a pure read.
- **Ticket with no `Description`/`TicketComment`s** — still generates a reply purely from `Title`/`Category`/`Priority`/`Status` (e.g. an initial acknowledgement-style reply); the prompt explicitly states `"No internal comments yet."`.
- **Calling this endpoint repeatedly** — each call is independent and may return a different suggestion (the AI provider is not seeded with a fixed random seed); no caching layer is introduced by this story.
- **Agent sends the suggested text without editing it** — this story has no way to detect or discourage that; treated as an accepted product decision, not a defect, mirroring how `QuickReplyTemplate` bodies are also sent unedited today.
- **Follow-up flagged, not implemented**: multiple ranked suggestions per call; direct "send this suggestion" one-click action wired to `SendMessageCommand` (would require resolving which `Conversation` the reply targets, which requires a `Ticket`↔`Conversation` link this codebase does not have — see Story Goal).
